Cursor 实战：2 个 Agent 并行改代码

你在 Cursor 里同时开了两个对话。一个改导出按钮，另一个补 CSV 解析测试。结果第二个 Agent 拿着第一个刚改到一半的代码跑测试，谁的改动让构建变红都搞不清。下一次让两项工作从同一个提交出发，各去一个 Git worktree。

要点速览

  • Cursor 的 Agents Window 可以让每个 Agent 在单独的 Git 检出目录里工作。
  • 用两项独立的小任务起步，各自限定改动范围和交付物。
  • 用一份初始化配置安装依赖，完成后逐份收回补丁，再跑合并后的组合测试。

两个对话，两个可运行的目录

Git worktree 允许同一个仓库拥有多个检出目录。每个目录有自己的工作文件和索引，可以同时站在不同的分支上。于是 A 安装依赖、修改组件时，B 的测试还能在自己的检出目录继续跑。你也可以在主工作区继续读代码或写文档。

图片来源：Cursor 3 发布文章本地与云端切换演示，2026-04-02。

下面这组练习可以用样例仓库跑一遍。第一次用，挑一份你熟悉、单测能独立跑的小仓库。先把两个任务共同依赖的代码整理成一个提交并记下哈希。当前正在编写的内容如果需要被两个任务引用，把它提交到自己的起点分支，让两个 Agent 都从这里开始。

交给谁 交付目标 允许改动
Agent A 导出按钮点击后立即禁用，完成时恢复 按钮组件和组件测试
Agent B 给 CSV 解析补上空行和引号样例 CSV 解析测试与 fixtures

如果手头只有一个问题，但想比较两套解法，也可以给两份 worktree 同一条任务，最后只收一个补丁。分工时把文件范围写清楚。比较方案时则固定输入、预期行为和测试命令，让两份结果落在同一把尺上。

在 Agents Window 分出两条线

  • 在 Cursor 命令面板打开 Agents Window，选择已有 Git 仓库。
  • 分别新建两个会话，在 Agents Window 中将每个会话启动在 worktree 中，也可以把已有会话移入 worktree。让两次检出以同一提交为基准。经典 IDE 走 Worktree Skills，3.0 更新日志列出的入口是 /worktree。
  • 各自给一条限定范围的任务。随提示附上项目里实际可跑的测试命令，要求记录执行结果、主要变化和剩余疑问。

图片来源：Cursor Worktrees 更新演示，2026-04-24。

可以把 A 的提示直接写成这样。只动导出按钮和它的组件测试。开始导出时给用户即时反馈，完成或报错后恢复按钮。沿用当前接口和样式。列出变更文件和实际跑过的测试，提交留在本次工作分支。

给 B 的提示可以更短。只补 CSV 解析的回归测试与最小样例数据。如果现有实现对某个用例失败，记录复现输入和实际输出，保持业务代码原样。这样 B 即使暴露一个旧 Bug，也能单独变成后续任务。

初始化一次写好，每个 worktree 自动执行

新检出目录经常缺 node_modules。官方文档说明 Cursor 创建 worktree 时会读取仓库下的 .cursor/worktrees.json。以有 lockfile、支持 npm ci 的 Node 项目为例。

{
  "setup-worktree": ["npm ci"]
}

把这份设置放进两个会话共用的起点。如果项目用 pnpm，把例子替换成项目已有的安装命令。团队需要区分不同操作系统时，官方文档也列出了平台专属配置项。

被 Git 忽略的环境文件不会凭空出现在新目录。有测试配置模板就由初始化步骤从模板生成。需要凭据的操作，可以改用测试账户或本地替身。要同时开两个本地服务，给它们分配不同端口，避免打开 A 的 URL 却浏览到 B。

如果初始化花了两分钟，先在其中一个目录确认依赖安装正常，再开第二个。日常开发只需要跑组件单测时，没必要让每个目录都起同一套数据库和前端服务。把初始化缩到两项任务都用得上的部分，其余步骤写进对应任务。

图片来源：Cursor 3 发布文章源文件浏览演示，2026-04-02。

收回补丁的顺序比启动顺序更重要

结束时在 Agents Window 打开两份改动，先浏览文件范围和测试摘要。可以在各自的 checkout 继续修、提交或开 PR，也可以把结果带回主工作区。下面这个顺序适用于两份改动都要留下的情况。

图片来源：Cursor 3 发布文章提交与 PR 演示，2026-04-02。

先拿 A 的结果，跑一次导出按钮的测试。再拿 B 的测试改动，跑解析相关用例。最后在同时包含两份改动的分支上跑原来的构建和组合测试。两个目录各自全绿只覆盖了两个中间状态，团队最终使用的是合在一起的版本。

如果两个任务都碰了 lockfile、全局类型或公共组件，收回时仍可能冲突。从差异更小、可独立交付的一份开始。让第二个任务在新基线上重新跑一次，旧 worktree 留到补丁和结果都保存好再清理。

这种分离发生在 Git 工作目录。两个 Agent 仍可能共享机器、端口、全局缓存和账号权限。从两路并行起步，记录每条任务的实际等待时间。如果多数时间花在装依赖或争用资源，先改善本地环境，再增加会话。

一句话总结：让两个 Agent 从同一个提交出发，在两个 worktree 里独立工作，最后把可读、可跑的改动一份份带回主分支。
