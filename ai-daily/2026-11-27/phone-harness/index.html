Phone Harness 日涨100星，AI点真机

电脑上的编码 Agent 可以启动浏览器，可一旦工作落到只装在手机上的 App，它就经常停在「请你手动点一下」。Phone Harness 给 Agent 接了一双能在真机上点按、滑动和读屏的手。11 月 27 日午班抓取的 GitHub Trending Python 日榜里，它排第 21，累计 5,946 星，页面显示今日新增 100 星。

要点速览

  • iPhone 走 Mac 的 iPhone Mirroring，Android 走 adb，两边都能用同一组 Python 辅助函数。
  • 一端靠屏幕文字识别，另一端能读无障碍树。两个平台的页面结构和按钮名称仍可能不同。
  • 首次上手可以只让 Agent 读一屏天气，或者给自己的样例 App 跑一轮只读巡检。
  • 真机的授权、解锁和需要生物认证的环节仍要由人接手。

让模型读一屏，再决定下一下点哪

项目官方演示用 iPhone 上的网约车界面串起长流程。画面里，电脑端的 Agent 发起操作，手机界面随操作变化。这条链实际由小动作拼成。先识别页面上的字，定位控件，再执行点击或滑动，随后读回新页面。页面没切过去，就停下来重新判断。

图片来源：Phone Harness 官方仓库 README，演示动图截帧，2026-11-27 查阅。

这类入口适合补一段移动端反馈。比如团队已经跑完后端和网页测试，还想知道手机在较大字体下能否打开设置、目标标签会不会折行。把结果写成「起始页面、已完成的动作、最后看到的文字」，比只留下「已完成」更方便复现。

官方视频表明这一套能串起某个任务。换一台设备、换一个语言或换到没有文本标签的页面，都可能需要调提示和读屏方式。项目未给出跨 App 的成功率。热度可以从榜单读出，可靠性得从自己的场景里找。

iPhone 从窗口看，Android 从 adb 读

本地设备 屏幕信号 连接条件
iPhone 镜像窗口截图，Apple Vision OCR macOS 15+、iOS 18+、完成配对
Android adb 截图，借无障碍树读文字 装 adb，在测试机打开 USB 调试

在 iPhone 上，Phone Harness 抓取 Mac 里的镜像窗口，再用 Apple Vision 识别文字。调用工具的应用还需要 macOS 辅助功能和屏幕录制权限。Apple 的镜像本身要求设备使用同一 Apple 账户并启用双重认证，手机保持锁定、放在电脑附近。

图片来源：Apple Support《iPhone Mirroring》，2026-10-14。

Android 路线适合手上已经有开发机的团队。adb 负责截图和输入，文字主要来自无障碍树。入口统一以后，Agent 可以用类似的方式表达「打开」「读屏」「点按」，各自的页面差异仍要写进任务。文字按钮可以优先按名称找，没标签的图标需要截图和支持视觉的模型。

图片来源：Android Developers《Run apps on a hardware device》，2026-11-13 更新。

第一次就做一轮只读巡检

  1. 先用测试设备。 iPhone 先在人手上完成镜像配对。Android 建议先走 USB，理解调试授权提示后确认。项目安装文档给出命令 uv tool install --python 3.12 --upgrade --force phone-harness。
  2. 让 Agent 认识这组工具。 用 phone-harness skill 获取项目提供的技能说明，按所用编码工具的方式注册。再跑 phone-harness doctor，先把设备连接稳定下来。
  3. 给明确的起点和终点。 示例任务可以是「打开测试机上的天气 App，读取当前屏可见的最高和最低温，保留原单位。遇到定位授权弹窗就停下，直接描述弹窗」。
  4. 读回证据。 项目提供 open_app() 和 screen()。前者让 Agent 到达目标，后者把可见文本交回来。也可以让 Agent 记录页面标题与是否弹出了授权提示，方便下一次重跑。
  5. 再把任务挪到自家 App。 比如打开语言设置、读取当前值、回到首页。这条路径够短，也很容易靠肉眼比对结果。等连续几次都走通，再加第二个设备或一种语言。

如果 App 刚启动就会弹系统权限对话框，先给模型规定停在哪一屏。Agent 是沿着当时的手机状态走的。旧账号、残留对话框或首次启动引导都可能改变路径。记录起始条件后，复跑才有参照。

一段有用的脚本，通常很短

第一类合适的活是给自家移动 App 落一条人眼容易复现的路径。第二类是看第三方 App 当前屏的公开信息，例如用一台测试机读天气。要保留长期回归能力，原有的应用级测试仍能提供稳定的控件标识和详细日志，Phone Harness 适合补那些走在两套系统中间的步骤。

限制也很具体。解锁 iPhone 会中断镜像。项目列出的边界还有多点触控、相机、Face ID，以及可能显示黑屏的受保护视频。让工具在这些入口前暂停，既省重跑时间，也让接手的人知道当前做到哪一步。

如果同一条路径要跑两个系统，先把目标写成可观察结果。例如「写出当前语言并回到首页」，而不是直接规定「点击左上角」。给 iPhone 和 Android 各保留一份首屏截图，界面变动时也能快速分辨是入口位置变了，还是设备根本没有连上。

Phone Harness 最适合从一条两端都能复跑的短路径开始，把手机上过去靠口头转述的状态变成 Agent 能读回的结果。
