腾讯三季报与 Hy4 flash：办公智能体的算力账

办公智能体需求把腾讯的资本开支和现金流推到新位置，Hy4 flash 是同一笔账的另一端，要把单个任务做便宜。 据澎湃新闻报道，腾讯 11 月 18 日披露的三季报把 WorkBuddy 推理需求列为算力预付款的用途之一。两天前，腾讯发布 Hy4 flash，把一份文档或一套演示文稿的处理成本摆到了模型参数与 API 单价旁边。[1][3]

算力预付款改变了这一季的现金流

据澎湃新闻报道，腾讯三季报披露了以下数据。同比均以上年同期同一指标为基准，金额单位为人民币亿元。[1]

指标 本期金额或口径 比较基准或补充口径
三季度收入 2073.36 同比增长 8%
三季度非国际财务报告准则（非 IFRS）经营盈利 同比下降 6% 剔除新 AI 产品贡献后为 833 亿元，按该口径同比增长 8%
三季度资本开支 814.33 上年同期 129.83，按该基数增长 527%
前三季度资本开支 1661.53 同比增长 179%
三季度自由现金流 −691 剔除大额算力采购预付款后为正 169
季末债务净额 三季度末净债务 137 二季度末为净现金 582

据澎湃新闻报道，大额算力采购预付款用于支持混元 Hy 系列升级、WorkBuddy 推理需求等。报告口径下的自由现金流为负，剔除这笔预付款后为正。同一家公司的两种口径，反映了实际现金流出和付款时点的影响。[1]

对技术负责人而言，资本开支反映的是腾讯为一系列算力需求安排的投入。WorkBuddy 的单任务推理成本反映的是模型执行一次工作的开销。预付款可能集中在一个季度，模型的单次调用则伴随每次请求发生。做采购预算时，这两个尺度回答的是资源何时备齐，以及产品运行起来后每多完成一份工作要花多少钱。

据澎湃新闻报道，腾讯首次披露的 WorkBuddy 数据包括以下四项。[1]

  • 日活跃用户超过 1000 万，衡量每天有多少人使用产品。
  • 日均消耗超过 100 万亿词元，衡量模型每天处理的词元规模。
  • 自 3 月上线以来累计收到 90 亿次用户任务请求，衡量用户发起工作的频次。
  • 企业版覆盖中国 500 强企业中的 50%，衡量产品在这组企业中的触达范围。

对办公智能体，一次任务请求可以包含多轮生成。比如修复表格，用户提供原始文件，模型可能需要查看数据、修改公式并检查结果。WorkBuddy 披露的请求量体现了需求规模，判断这些需求要占用多少算力，还要看每次执行经过多少轮，以及失败后会不会重试。

元宝与小微把资源聚到模型能力和微信入口

据北京日报客户端报道，腾讯的刘炽平在财报电话会上说，“元宝没有我们预期的那样成功”。他表示，元宝不再只把用户规模当作目标，重心回到提升模型能力，腾讯也已大幅削减在元宝上的投入。[2]

同一报道提到，微信 AI 助手“小微”日活跃用户为 3000 万。把元宝的调整与小微的使用规模放在一起看，腾讯正在把资源聚到模型能力和微信入口。对接入方而言，模型能做什么、用户在哪里使用，是两项可以分别验证的产品条件。[2]

Hy4 flash 同时减少缓存占用和生成量

图片来源：腾讯混元 Hy4 flash 发布稿配图（经科技日报转载），2026-11-16。

腾讯把 Hy4 flash 的优化放到了预训练、后训练和推理三个环节。发布稿与美国 Hugging Face 上的腾讯模型卡对总参数采用了不同数字，激活参数一致。表中 API 价格以人民币计，单位为元／百万词元。[3][4][5]

腾讯模型 总参数 激活参数 上下文 API 价格
Hy4 flash 发布稿 2240 亿，模型卡 2200 亿，两者均含 640 亿 Engram 参数 120 亿 发布稿为 1M，模型卡为 1,048,576 词元 输入 0.5，输出 2，命中缓存 0.02
Hy4 — — — —
Hy4 preview 7700 亿 490 亿 — —

总参数和激活参数各有用处。前者描述模型规模，后者描述运行时用到的参数规模。上下文说明一次能处理多长的输入输出序列，价格列则让调用方能按输入、输出和缓存命中分别估算费用。

  • 预训练减少缓存占用。 腾讯引入混合注意力、LatentMoE 与 Engram，称 Hy4 flash 的键值缓存（KV cache）占用为 Hy3 的 1/24、Hy4 的 1/6。对反复读取长文档的任务，这项变化关系到推理时要留多少空间给上下文。[3][4]
  • 后训练缩短生成。 腾讯用 Hy4 做自蒸馏，并通过强化学习把端到端任务输出长度较优化前缩短 50%。如果交付物质量可接受，少生成一部分内容就能少支付相应的输出费用。[3][4]
  • 推理优化提高解码速度。 腾讯结合 megakernel、4 位量化和 DFly，公布的解码速度超过每秒 150 个词元。这个指标描述生成阶段的速度，用户等到文件交付的时间还包括读取、工具执行和结果检查。[3][4]

API 单价给每一类词元标价，模型改动则影响一个任务实际要处理和生成多少词元。两类数字放在一起，能解释为什么同样一份文件交给不同模型，最终费用会不同。

WorkIndex 的成本优势与用户盲测各有口径

图片来源：腾讯混元 Hy4 flash 发布稿配图（经科技日报转载），2026-11-16。

WorkIndex 把计费单位从词元换成了任务。它是腾讯围绕 WorkBuddy 典型任务自建的内部评测，覆盖演示文稿制作与修改、文档编辑、表格修复等工作。按腾讯发布稿的计价口径，Hy4 flash 的单任务成本约为以下模型的相应比例。[3][4]

  • Hy4 preview 的 1/13，分母是 Hy4 preview 在 WorkIndex 上的单任务成本。
  • Hy4 的 1/20，分母是 Hy4 在同一评测上的单任务成本。
  • DeepSeek-V4.1-Flash-1017 的 1/8，比较对象用 Max 档和 DeepSeek 的忙时价格计算。

这些比例说明，在腾讯选取的办公任务和计价条件下，用 Hy4 flash 处理每项工作平均花费更低。换一种任务组合，或者换掉 DeepSeek 忙时价格，费用差距也要随之重新计算。

图片来源：腾讯混元 Hy4 flash 发布稿配图（经科技日报转载），2026-11-16。

腾讯另邀请 85 位内部 WorkBuddy 用户参加盲测，涉及 27 类、共 259 个任务。四款模型的满意度采用 4 分制，外部模型在这项盲测里均用 high 档。这一计价和测试设置与 WorkIndex 的 Max 档忙时价格比较分属两项评估。[4]

模型（厂商） 满意度（满分 4 分） 端到端时长中位数（分钟） 单任务成本（元）
DeepSeek-V4.1-Flash-1017（中国 DeepSeek） 3.09 10.3 1.20
Hy4 flash（中国腾讯） 2.79 6.7 0.26
Claude-Haiku-5.5（美国 Anthropic） 2.81 6.8 4.73
GLM-5.3-Flash（中国智谱） 2.53 7.6 0.81

按盲测表，Hy4 flash 的单任务成本最低，端到端时长中位数也是表中最低。满意度低于 DeepSeek-V4.1-Flash-1017，略低于 Claude-Haiku-5.5。对办公室里的表格和文稿，收到结果的速度、花费，以及结果能否直接交给同事，值得分别度量。[4]

图片来源：Hugging Face 模型卡 tencent/Hy4-flash，Figure 1，2026-11。

腾讯模型卡列出的 WorkIndex 任务得分中，Hy4 flash 为 42.1，Hy4 preview 为 39.7，Hy4 为 51.4。沿着成本和得分两个坐标看，Hy4 flash 提供了更低开销的办公选项，Hy4 则在同一评测中取得更高得分。[5]

图片来源：Hugging Face 模型卡 tencent/Hy4-flash，2026-11。

腾讯模型卡还把公开智能体评测的得分与成本画在同一张图上，其中包括 DeepSWE 和 OSWorld 2.1。公开评测扩大了观察范围，内部用户盲测则补充了满意度和用时。对采用 WorkBuddy 的团队，自己文档里的格式要求和验收条件还要放回实际任务里量。[3][5]

开放权重让团队能用自己的办公任务算账

图片来源：Hugging Face 模型卡 tencent/Hy4-flash，预训练评估图，2026-11。

这张腾讯模型卡里的预训练评估图把基础模型的 BPB 与激活参数量并列展示。它对应的是基础模型的评估维度。办公产品还要看后训练之后的模型在实际工作中交出了什么文件，以及用户修改了多少才愿意采用。[5]

  • 腾讯已在 Hugging Face 放出 Hy4 flash、Hy4 flash-FP8 和 Hy4 flash-Base 权重，采用 Tencent Hy License，使用前可读许可。模型卡要求从指定的 transformers 提交安装支持版本，这会影响自部署团队准备运行环境的方式。[5]
  • 腾讯宣布 WorkBuddy 在 11 月 30 日前限时免费，腾讯云 TokenHub API 在这一窗口按原价的五折计费。试用能减少首次测试的开销，长期预算可以按常规单价另算。[3][4]
  • 腾讯团队建议把深度搜索、文档处理、PPT 生成、简单前端展示和电脑操作交给 Hy4 flash，把长程软件工程等复杂任务交给 Hy4。这给按任务选择模型提供了一个可以用真实工作验证的起点。[3][4]

选择一份平时要交付的 PPT、一张需要修复的表格或一份待修订的文档，在相同输入、工具权限和验收条件下换模型执行。对 PPT，可以看关键数字和章节是否齐全。对表格，可以核对公式与结果。对文档，可以请日常接收文件的同事判断是否够用。

每个完成任务的成本可以用所有尝试的推理开销除以通过验收的任务数，计入失败和重试的费用。时长从发出请求算到拿到可交付结果，补跑也算在内。可接受率以提交评测的任务总数为分母，记录其中达到验收标准的比例。这样，模型生成得快、账单金额低和文件交得稳，都能在同一次试用里得到回答。

试用时还可以把任务按工作量分组，比如把改一页 PPT 和重做整套演示文稿分开。平均数容易把修订范围不同的工作混在一起。同一组任务里的结果更容易解释，也方便判断哪些需求可以交给 Hy4 flash，哪些适合转给 Hy4。

腾讯提前为办公智能体安排算力，Hy4 flash 则让团队有机会以更低的成本稳定交付每一张表、每一份文稿。
