Claude Code两将确认加入OpenAI，争夺AI编程工作台

北京时间 11 月 26 日凌晨 3 点 38 分，前 Claude Code 工程师 Thariq Shihipar 发帖确认加入 OpenAI。三周前，Claude Code 前产品负责人 Cat Wu 已宣布去 OpenAI 负责核心产品的产品管理。一个月内两位熟悉 Claude Code 的人去了同一家公司，AI 编程赛道的人才争夺有了新进展。

要点速览

  • Thariq 公开确认加入 OpenAI，点名期待和 Cat Wu、Thibault Sottiaux 等同事共事，具体职位尚未披露。
  • Cat Wu 11 月 5 日已公开自己的职责，负责 OpenAI Core Products 的产品管理。
  • Thariq 在公开交流中谈过智能体提问功能，也整理过 Anthropic 内部数百个 Skills 的使用经验。
  • OpenAI 本月还宣布拟收购 Pierre。Codex 已经在用这家公司的文件树和代码差异库。

隔了三周，两条消息接上了

Thariq 在 10 月下旬离开 Anthropic，结束了在 Claude Code 团队一年多的工作。他今天在帖里说，自己为过去在 Anthropic 的工作感到骄傲，也会继续为旧同事加油。他列出了多位未来同事，尚未公布负责哪条产品线。

Cat Wu 的分工更明确。她曾参与 Claude Code 从内部工具走向公开产品。在 Anthropic 的官方活动里，她和团队讲过这款工具的起点，也演示过如何把它接进现有代码库。如今她在 OpenAI 负责 Core Products 的产品管理。

Cat Wu 前产品负责人，参与产品从内部工具走向用户 11 月 5 日确认负责 Core Products 产品管理

图片来源：Anthropic《Claude Code Live》活动页面，2026-11-26 查阅。

一个好问题能省下一轮返工

在 Claude Code 团队的公开交流里，Thariq 谈过 AskUserQuestion。举个开发场景，你让智能体重做搜索页，需求却没交代旧链接怎么办。智能体可以中途暂停，把需要用户拍板的选项摆出来，等选定方向后继续。

这个细节的价值在于减少返工。保留旧链接可能意味着多写一层兼容逻辑，直接换路径可能影响已经发出去的链接。让模型把这个分岔摆在面前，往往比等它写完整个功能、再从一长串改动里倒找决策更省时间。

Claude Code 的另一项产品功夫是把团队经验装进 Skills。Thariq 在 6 月写过，Anthropic 内部已有数百个活跃 Skills，经整理可分成 9 类，从内部 API 参考到代码评审和发布。团队积攒的是具体做法，比如写周报该读哪份记录，碰到含糊字段该去哪里找定义。

图片来源：Thariq Shihipar 在 claude.dev 发布的 Claude Code Skills 实践，2026-06-03。

团队经验可以跟着项目走

一个 Skill 可以是个目录，里面放 SKILL.md，并按需放示例、参考资料和脚本。Anthropic 的说明把读取分成几步，先给模型名称和描述，匹配任务后再读正文，需要时才打开相关文件。流程有了固定的存放处，日常对话也少背一份又一份长说明。

图片来源：Anthropic Engineering《Equipping agents for the real world with Agent Skills》，2025-10-16。

想象有个新同事让智能体加一张设置页，仓库里已有三套样式，只有一套还在维护。团队可以把组件约定、示例目录和本地启动步骤写进 Skill。以后改这个项目的人都能用同一套说明，约定变化时也有明确的文件可改。

Codex 桌面版在 2 月推出时就有 Skills 管理界面，还内置了 Git worktree。并行任务可以各自在隔离的工作目录里改代码。开发者在同一个工作台翻差异、补评论，再决定要留下哪一版。两边都已在做流程复用，差异会落到平时怎么接手任务上。

OpenAI 连代码评审界面都在补

11 月 4 日，OpenAI 宣布拟收购 Pierre Computer Company。Codex 里浏览文件用到的 Trees、读代码改动用到的 Diffs，已经来自这家公司。公告说，交割后还计划把 Code Storage 的功能接进 Codex。

图片来源：OpenAI Developers《Mastering remote engineering work from your phone》，2026-06-23。

假设开发者同时派两个任务，一个给长列表加虚拟滚动，另一个修复换筛选条件后页面跳回顶部。两边都可能碰同一段代码。最后费脑子的环节是弄清每条线程动了什么，以及两次修改合起来会不会打架。

一份逐行显示增删的差异，可以把争议拉回到具体代码。文件树让接手的人先定位改动最多的地方，行内评论能把追问钉在那一行。离开椅子之后，ChatGPT 手机端的 Codex Remote 也能翻差异、标注行并把反馈送回任务。

OpenAI 在 6 月披露，当时 Codex 已有超过 500 万周活跃用户，较 2 月桌面应用推出时增至六倍以上。这个历史数字给今天的人事消息提供了背景。到了这个规模，改一处评审交互，影响的是许多团队反复经历的日常交付。

下一场竞争就在合并按钮旁

Thariq 的新岗位还没有发布，Codex 的现有界面也早于这次入职。把两件事放进今年的产品轨迹里，能看到 OpenAI 已经在往代码浏览、历史记录和评审投资源，同时吸引了做过另一套编码智能体的人。

开发者最先感受到的差别，很可能就藏在一次普通提交里。智能体如果能尽早问清兼容性、按团队习惯改完，再把两处关键取舍留在差异里，接手的人就能沿着上下文继续干活。并行改动越多，这段交接越值钱。

AI 编程已经争到了提交前的最后一步，谁让开发者更轻松地接住 AI 写的代码，谁就更可能成为团队每天打开的工作台。
