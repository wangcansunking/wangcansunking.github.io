Claude 零留存进入公测，企业要接手哪些工作

11 月 23 日，Anthropic 把 Enterprise Frontier Safeguards（EFS）推进到公测。符合条件的企业可让 Anthropic 对提示和响应实行零留存，同时把加密的安全数据写入企业自己的云账户。对采购方来说，签约前值得问清的一件事是，推理、存储和人工复核分别由谁负责。

要点速览

  • 公测更新列出 Claude Platform、Claude Platform on AWS 和 Anthropic 托管的 Claude Models on Google Cloud。
  • 加密副本落在客户自己的存储桶，企业团队审理系统标记的安全事件。
  • 在 Claude Platform 上，配置作用于整个工作区。文件、批处理等独立功能另有留存规则。
  • Anthropic 对 EFS 本身不另计费，存储、读写和传输费用仍按云账单结算。

九月的设计，十一月开放测试

Anthropic 9 月公布设计时，谈到金融、支付和企业软件用户不愿再增加一处敏感数据仓库。报告列出 Salesforce、Visa 和 Mastercard 等参与反馈的机构。它们已有加密、权限和审计制度，增加一个存储供应商还牵涉合同和内部审批。

11 月的发布日志明确了公测覆盖的入口。新闻稿还讨论过其他渠道，因此评估时应以对应渠道的上线文档、资格条款和管理员页面为准。先找负责采购的组织和实际调用模型的账号，再查这两个身份能否使用同一套控制。

图片来源：Claude Platform 官方发布日志 · 11 月 23 日公测原文（原网页局部截图），2026-11-23。

零留存之后，数据在哪里

官方把加密副本称为 Sealed Safety Data。它包含提示、回复和模型推理，按 Anthropic 的封存格式写入客户的云桶。产品文档说明，企业团队即使拥有那个桶，也不能直接读出这批封存数据。

权限由此分成两条。基础设施团队负责存储访问、密钥和保留设置。安全团队处理自动监测发来的案件，核查工单上下文并决定怎么响应。把桶交给同一位云管理员，并不会自动给企业配齐案件处理流程。

图片来源：Claude Platform 官方 EFS 说明 · 客户存储与内部复核（原网页局部截图），2026-11-24。

对象 运行方式 部署时确认
Messages API 推理请求 按工作区应用 EFS 核对 API key 或工作区 ID
封存数据 加密写入客户云桶 容量、密钥和访问策略
安全案件 交客户团队复核 值班、授权和升级路径

工作区是配置单元

Claude Platform 的配置在工作区层面生效，覆盖其中所有模型的消息请求。假如业务只有合同摘要需要 EFS，可以给它独立的工作区和凭据。验收时应用团队应核对实际请求所用的 API key 或显式传入的工作区 ID，尤其是多个项目共用网关的情况。

图片来源：Claude Platform 官方 EFS 说明 · 工作区流量范围（原网页局部截图），2026-11-24。

同一段业务流程可能包含文件上传、消息调用以及运行工具。官方把 Files API 上传、Batch API 结果、代码执行容器和 Managed Agents 会话列在适用范围之外。若应用在调用前自行记下 prompt，企业也得把自己的日志和追踪平台纳入排查。

图片来源：Claude Platform 官方 EFS 说明 · Messages API 适用范围（原网页局部截图），2026-11-24。

举个例子，客服分析服务可以先从工单系统只读提取公开字段，把文本交给已配置的 Messages API 工作区。若后来改为把整份原始附件上传到文件产品来做分析，数据路径会增加一环。这个改动需要重新检查附件的删除和访问办法。

费用与值班怎样落地

官方说明，EFS 不额外收费，也不改模型 API 的费率或限流。云端可能按存储、读写、密钥操作和网络传输收费。若团队有跨区备份和大量短请求，试点应观察对象增量、各项操作费用以及费用落在哪个部门。

图片来源：Anthropic 官方 EFS 设计说明 · 产品设计阶段的客户反馈（原网页局部截图），2026-09-01。

11 月 23 日的日志还新增两类组织 webhook 事件，对应客户自有桶未通过日常检查和恢复通过。试点可以先指定存储告警的值班人，再约定什么时候由平台团队查策略变更、什么时候把问题升级给业务负责人。

图片来源：Claude Platform 官方发布日志 · 存储状态通知（原网页局部截图），2026-11-23。

企业内部的人工复核需要第二套验收。可以用预先约定的演练通知，确认值班人员能定位工作区和请求、联系应用责任人，并把处置结果记录进内部工单。这样可以检验谁能收到信息、谁有权决定下一步，以及交班后有没有人接手。

现有企业合同的复审也会变化。只写一句“供应商零留存”，采购方难以验收客户桶、附件和内部日志。逐项约定适用入口、数据生命周期、告警接收方和人员权限，才方便在模型、应用或渠道换代时重做核对。

上线清单可以按请求类型交给不同业务负责人。聊天摘要团队核对工作区和消息调用，文档团队核对文件生命周期，平台团队核对桶和监测。三方分别留下一次验证记录，新业务接入时就能看出哪些假设需要重审。

试点如何覆盖故障链

准备一个只接收公开样本的工作区，记录测试开始前的桶和密钥设置。把普通长文本、带工具的消息和单独上传文件的流程各走一遍。对每条路径记下请求标识、服务入口、哪一方必须能查到记录，以及是否有删除入口。

客户环境还应考虑谁能修改配置。若值班人员同时可以更改保留策略、关闭告警和关闭工单，企业内部很难复查一次事故的经过。试点可以让应用、云平台和审计人员分别验证自己看到的记录，再由同一个变更单串联。

多云企业尤其要区分购买入口和存储位置。Claude Platform on AWS 与 Amazon Bedrock 即便同属 AWS，也对应不同服务和管理界面。谷歌渠道也应核对开发团队实际使用的产品名。部署清单写具体入口，方便业务迁移后重做验证。

用量估算可以从两个量开始，一周新增多少对象，复核工作一周占用几个人时。前者影响云账单，后者影响审计班表。等第二批工作区上线后重测一次，就能判断组织是否需要统一的配置模板和事件入口。

换模型时也应保留一份变更前后对照。记录接入方名称、工作区和使用的接口，随后核对谁保管加密数据。这个小动作能帮助企业在转用新模型、更新网关或重谈合同后继续确认零留存条款是否对准真实流量。

如果采购条款同时要求区域边界，试点还应把桶所在区域、备份位置和服务接入区域一起写入记录。每项检查都指向一个具体的管理员界面或合同条款，便于后续审计复查。

EFS 的价值在于让企业掌握安全数据的存储和复核职责，能否规模化使用取决于这些职责在日常业务中是否有人承担。
